Security & Auth

JWT Authentication Flow

Definition: JSON Web Token (JWT) is an open standard (RFC 7519) that defines a compact and self-contained way for securely transmitting information between parties as a JSON object.

মডার্ন ওয়েব অ্যাপ্লিকেশনে API সিকিউর করার জন্য Session-এর বদলে বর্তমানে Stateless Authentication বা JWT ব্যবহার করা হয়। চলুন দেখি আন্ডার-দ্য-হুড এটি কীভাবে কাজ করে!

1. The Architecture: Stateless Security

ঐতিহ্যবাহী (Traditional) সার্ভারগুলো Sessions ব্যবহার করত। অর্থাৎ, একজন ইউজার লগইন করলে সার্ভার তার ডাটাবেস বা RAM-এ ইউজারের ইনফরমেশন সেভ করে রাখতো এবং ব্রাউজারকে একটি Session ID দিত। কিন্তু সমস্যা হলো, যখন আপনার অ্যাপে লাখ লাখ ইউজার আসবে বা একাধিক সার্ভার (Load Balancer) ব্যবহার করবেন, তখন প্রতিটি রিকোয়েস্টে ডাটাবেস চেক করা সার্ভারের জন্য অনেক ব্যয়বহুল (expensive) হয়ে যায়।

এর সমাধান হিসেবেই এসেছে Stateless Architecture বা JWT। এখানে সার্ভার ইউজারের কোনো তথ্য নিজের কাছে সেভ রাখে না!

Stateful (Session Cookies)

  • সার্ভার সেশন ডাটা মেমোরি বা ডাটাবেসে স্টোর করে।
  • মাল্টিপল সার্ভারে স্কেল (Scale) করা বেশ কঠিন।
  • প্রতিটি Protected Route-এ ডাটাবেস কোয়েরি চালাতে হয়।

Stateless (JWT)

  • সার্ভার কোনো সেশন ডাটা স্টোর করে না (Self-contained)।
  • খুব সহজেই স্কেল করা যায়।
  • সার্ভার শুধুমাত্র একটি Secret Key দিয়ে গাণিতিকভাবে টোকেনের Signature ভেরিফাই করে।
The Golden Rule: JWTs are Encoded, not Encrypted. যে কেউ চাইলেই টোকেন ডিকোড করে ভেতরের ডাটা পড়তে পারবে। এর আসল সিকিউরিটি হলো এর Signature। কেউ যদি ভেতরের ডাটা টেম্পার (পরিবর্তন) করার চেষ্টা করে, তবে সিগনেচারটি ইনভ্যালিড হয়ে যাবে এবং সার্ভার সেটি রিজেক্ট করে দিবে।

2. Node.js Implementation (Sign & Verify)

নিচের কোড স্নিপেটে দেখানো হয়েছে কিভাবে Express.js এ একজন ইউজার লগইন করার পর টোকেন জেনারেট (Sign) করতে হয় এবং পরবর্তীতে প্রটেক্টেড রাউটের জন্য সেই টোকেন ভেরিফাই (Verify) করতে হয়।

authController.js 
const jwt = require('jsonwebtoken');

// 1. Generate Token on Login
exports.login = async (req, res) => {
    const user = { id: "64a1b2", role: "admin" };
    
    // Signing the token with a Secret Key
    const accessToken = jwt.sign(
        user, 
        process.env.JWT_SECRET, 
        { expiresIn: '15m' }
    );
    
    res.status(200).json({ token: accessToken });
};

// 2. Middleware to Protect Routes
exports.verifyToken = (req, res, next) => {
    const token = req.headers.authorization?.split(" ")[1];
    if (!token) return res.status(401).json({ msg: "No Token Provided" });

    jwt.verify(token, process.env.JWT_SECRET, (err, decoded) => {
        if (err) return res.status(403).json({ msg: "Token Expired or Invalid" });
        
        req.user = decoded; // Attaching decoded payload { id, role }
        next();
    });
};
