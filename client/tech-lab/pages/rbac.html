SECURITY ARCHITECTURE

Role-Based Access (RBAC)

Definition: Role-based access control (RBAC) is an authorization strategy that restricts network access based on the roles of individual users within an enterprise.

সিস্টেমের কিছু নির্দিষ্ট কাজ শুধু নির্দিষ্ট মানুষই করতে পারবে, এই পারমিশন লজিক হ্যান্ডেল করাই হলো RBAC। শুনতে খুব সহজ মনে হলেও, স্কেলেবল আর্কিটেকচারে এটি মেইনটেইন করা বেশ চ্যালেঞ্জিং।

1. The Spaghetti Code Problem

Architectural Challenge

ধরি, আমরা একটি এন্টারপ্রাইজ লেভেলের ই-কমার্স সিস্টেম বানাচ্ছি। শুরুতে আমাদের সিস্টেমে শুধু দুই ধরনের এক্সেস ছিল: User আর Admin। আমরা কন্ট্রোলারে খুব সহজেই লিখে ফেললাম: if (user.role === 'admin') { deleteProduct() }

সব ঠিকঠাকই কাজ করছিল। কিন্তু কয়েকদিন পর রিকোয়ারমেন্ট আসলো, আমাদের একজন Manager লাগবে যে প্রোডাক্ট আপডেট করতে পারবে কিন্তু ডিলিট করতে পারবে না। আবার একজন Support স্টাফ লাগবে যে শুধু রিড করতে পারবে। আমরা আবার কন্ট্রোলারে গিয়ে লিখলাম: if (role === 'admin' || role === 'manager') { editProduct() }

এভাবে প্রতিবার নতুন রোল আসার সাথে সাথে কন্ট্রোলারের ভেতর if-else এর চেইন বড় হতে থাকলে একসময় পুরো কোডবেস Spaghetti Code-এ পরিণত হবে। বিজনেস লজিক আর পারমিশন লজিক একসাথে মিলেমিশে একাকার হয়ে যাবে, যা মেইনটেইন করা অসম্ভব।

Bad Practice (Controller Level)

  • বিজনেস লজিকের ভেতরেই পারমিশন চেক করা হয়।
  • নতুন রোল যুক্ত হলে পুরো কোডবেস ঘাঁটতে হয়।
  • কোডের Reusability জিরো হয়ে যায়।

Pro Practice (Router Level)

  • বিজনেস লজিক থেকে পারমিশন লজিক পুরোপুরি আলাদা রাখা হয়।
  • সার্ভারের ডেটাবেস হিট করার আগেই রাউটার লেভেলে আনঅথোরাইজড ইউজারকে আটকে দেওয়া যায়।

2. The Middleware Solution (Express.js)

এর স্মার্ট সলিউশন হলো একটি ডাইনামিক Middleware Factory তৈরি করা। কন্ট্রোলারের ভেতরে আমরা পারমিশনের কোনো কোডই লিখবো না। আমরা রাউটারেই বলে দিবো এই এন্ডপয়েন্টে কারা ঢুকতে পারবে। ইউজারের রোল ম্যাচ না করলে কন্ট্রোলার রান হওয়ার আগেই 403 Forbidden রেসপন্স চলে যাবে।

routes/productRoutes.js 
// 1. The Dynamic Authorization Middleware
exports.authorizeRoles = (...allowedRoles) => {
    return (req, res, next) => {
        // req.user is populated by previous JWT verification middleware
        if (!allowedRoles.includes(req.user.role)) {
            return res.status(403).json({ 
                error: `Role: [${req.user.role}] is strictly prohibited from this action.` 
            });
        }
        next(); // Access Granted -> Move to Controller
    };
};

// 2. Clean, Declarative Routing
router.route('/products/:id')
    // Anyone can read
    .get(getProduct)  
    
    // Only Manager & Admin can update
    .put(verifyJWT, authorizeRoles('manager', 'admin'), updateProduct) 
    
    // ONLY Admin can delete
    .delete(verifyJWT, authorizeRoles('admin'), deleteProduct);
